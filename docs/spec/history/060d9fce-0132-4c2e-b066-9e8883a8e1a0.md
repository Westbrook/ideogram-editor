- Prefer real en-reve components, real browser input and actual local backend/persistence where practical. Define deterministic provider fixtures for rare errors/races and a separate opt-in, cost-bounded live API contract suite; fixtures never constitute live-provider verification. Default tests require no credentials.
- Cover the accepted compatibility matrix: valid operations, unsupported combinations, preserved drafts, no silent input/parameter changes, frozen submissions and explicit composite-versus-reference semantics.

- For deterministic canvas/compositing/masks assert geometry, alignment, alpha, output dimensions and preservation with justified tolerances. For generated content assert response contract, decoding, usable results and provenance; avoid fixed model pixels or exact generated text. Keep subjective model-quality evaluation separate.
- Set supported browser/device/accessibility targets and measurable axe, keyboard/focus, naming, shortcut/IME, zoom/reflow, contrast/non-color-only, RTL, reduced-motion and async-announcement acceptance. Include practical non-pointer editing paths and explicit manual assistive-technology evidence/limits.
- Include before/after examples of consumer-observable assertions. Reject coverage-only tests, private-implementation mirroring, brittle strings and snapshot-only proof.
- Define fixture lifecycle, isolation, retry/flake/quarantine ownership and expiry; quarantine must not silently remove critical acceptance.
- Specify app-owned commands/CI lanes, targeted versus broad execution, necessary clean-install validation, and evidence receipts. Adopt the design-system runner's applicable conventions without assuming its private tooling is importable.
- Map performance gates to Task 6 workload/environment/percentile targets, separate deterministic app gates from provider observations, and make benchmark contamination/variance policy explicit.
