## 1. Early constraint checkpoint for Tasks 3 and 4

1. Start with **one active provider request**, counting submission through provider terminal reconciliation, separate from **1–4 images per request**. Keep excess jobs durable locally. Higher limits need account evidence and the concurrency campaign below.
2. Design for the normal 2048×2048 / 20-layer / 10,000-event fixture and the tiled 5000×5000 / 100-layer / 100,000-event stress fixture. The latter is a local workload, not proof the provider accepts that exact auto size. Do not eagerly decode every layer or candidate.
3. Raster-only usable canvas target/ceiling: cold normal **2.5/4 s**; warm normal **1/2 s**. Pointer-to-paint p95 **16.7/33.4 ms** at 60 Hz, dropped-frame share **1/5%**. Separately budget application frame work at **8/10 ms** at 60 Hz. Every discrete action, including an expensive operation start, gets meaningful visible acknowledgement within **50/100 ms**, without claiming durable acceptance or completion. Component update completion alone does not prove painted pixels.
4. Total attributable browser process-tree RSS under the normal workload **1/1.5 GiB**, stress **1.5/2 GiB**; raster CPU allocation **384/512 MiB**, GPU allocation estimate **256/384 MiB**. Preserve original assets on disk; display-resolution caches can be evicted.
5. Durable records contain asset IDs and hashes, never image data URIs. Per-record target/ceiling **4/16 KiB**, document append p95 **20/50 ms**, normal snapshot-based replay **250/750 ms**. Group strokes/gestures; do not synchronously append each pointer sample.
6. Accepted requests freeze source/mask/adapter identities, settings and request transforms. Resize requires preview plus explicit approval; original bytes persist. Editor compositing enforces preservation outside masks. Performance fallback may change display resolution, never silently change provider settings, source content or output/export resolution.
7. Show queue state, elapsed time, transfer bytes and cancel-requested honestly. Provider queue/execution durations have **no promised numerical ceiling**. Instant is a separate prompt-only operation, not a speed switch for image/mask/LoRA. Finished queued results ship first; incremental image previews are deferred.
8. Browser rendering first, with a visible native loading/error shell. Versioned coherent en-reve archives are the consumer input; ordinary installation must not rebuild the design system. Package production has its own budget.
9. Preserve downloaded candidates until explicit deletion, including unused ones. Disk pressure pauses new allocations and offers user choices; it does not expire permanent assets automatically.
10. Task 4 adopts the phase/span contract in §8. Task 3 supplies busy/failure/fallback states and explicit previews against these budgets. Task 5 builds the gates; Task 7 records final reconciliation. This checkpoint does not authorize starting those tasks.

## 2. Qualification contract: how to read every budget

Every matrix row inherits this section and names its owner, workload, environment, sample/cache profile and enforcement class. That expanded combination is the complete budget record. Time values are elapsed wall time; memory is binary MiB/GiB; network rates use decimal Mbps; KiB excludes pixels unless stated. Target is the engineering objective; ceiling is the acceptance limit for the stated statistic, not a promise for every user's machine. Correctness, no data loss, no hidden input changes and zero-call replay are mandatory even when a performance exception exists.

**Accountable owners:** UI = editor frontend owner; Raster = renderer/worker owner; State = event/persistence owner; Jobs = backend scheduler/transport owner; Assets = owned-asset storage owner; Training = dataset/adapter owner; Build = editor build/CI owner; DS producer = en-reve archive producer. Task 4/5 must assign named maintainers before implementation release; the role is the owner until then. No unowned budget may become an exception.

### Outcome, eligibility and censored statistics

Every receipt reports attempted, expected-outcome, unexpected-error, timeout, infra-invalid and missing counts separately. A valid deterministic timing cohort requires **all** prescribed starts and expected outcomes (30 per expanded O/Q cache cell,10 per Q3-O/Q3-Q cache cell, three per PR O/Q cache cell, with all other profile-specific counts retained). Planned cancellations/faults are successful harness outcomes only when their specified state/feedback/attempt-count assertions pass; measure their declared response boundary, never generation-completion latency.

Gate priority is deterministic: (1) any app correctness/cap violation, unexpected app timeout/abort or measured ceiling breach = **FAIL**; (2) otherwise any missing required sample or documented infrastructure invalidation = **INCONCLUSIVE, blocks merge/release**; (3) otherwise evaluate complete statistics/relative regressions = PASS or FAIL. A target miss below ceiling is tracked, not a failure by itself. Infrastructure invalidation needs external evidence (runner lost, power/host fault), not merely a slow candidate. Invalidate the whole affected matched cache/workload cohort, retain it, and replace with one complete base/candidate cohort of the original count. Never top up just the slow/missing tail until green. One bounded diagnostic retry is permitted under §7; unresolved results remain blocked. An incomplete deterministic run cannot pass via its success-only percentile.

Exact completed times use nearest-rank k=ceil(p×n). Report success-only percentiles with n explicitly; they are diagnostic when the campaign is incomplete. For **all-attempt completion** distributions, a normal completed attempt is interval [t,t]; a right-censored timeout at T is [T,infinity), not a completion at T. When every attempt is timing-eligible, compute the kth ordered lower endpoint and kth ordered upper endpoint as quantile bounds. Equal finite endpoints establish an exact all-attempt quantile; otherwise report only [lower,upper] (infinite upper means lower-bound-only). Use conservative ≥T notation. Do not call a bounded estimate exact. Correctness-invalid output or unknown infrastructure abort is not an eligible completion duration: all-attempt completion quantile is unavailable, while counts, wall elapsed and separately labelled success-only diagnostics remain. Planned fault cohorts measure a different, fully defined response metric.

### Masked result preparation and adoption: exact stopwatch contract

**Ready states are different:** encoded-on-disk means validated owned bytes/hash exist; encoded-byte-ready means a requested encoded buffer/chunk has been read; decoded-surface-ready means pixels for the required surface/tile are available; **prepared** means the full editor-preserved composite has its own immutable, durable encoded asset plus recorded original/candidate/effective-mask/transform identity. Prepared does not imply its decoded viewport is still resident. A preview thumbnail is neither a full prepared composite nor decoded full-resolution evidence.

The effective mask, including the explicitly previewed feather transition, is frozen with the request. For every pixel outside that effective mask, the prepared result must equal the frozen original under the specified raster/color contract. R10 owns preservation computation; R12 owns each decode; R13 owns encoding; R27 owns durable asset verification/storage; State owns the parent R15 preparation/adoption timer. No timing shortcut may replace the original outside the mask, recompute against a changed document, or label an uncomposited provider result as adopted.

**R15 preparation** starts when all original/candidate/mask encoded assets and required transforms are durable and preparation is scheduled immediately; any app queue delay after that readiness is included. It stops only when the full preserved encoded asset is durable and a correctly prepared current viewport is decoded/paint-ready. Parent target/ceiling W1 1/2.5s, W2 5/12s. Child spans cover disk read, decode/worker transfer, preservation compute, encode, store/hash and viewport decode. Parent includes scheduling/IO gaps; it is not computed by adding or subtracting p95 values. If tiled decode/compute overlap, report monotonic active compute spans for R10 and their union/total as labelled, plus parent wall time; do not claim all pixels fit in memory simultaneously. An isolated R10 test begins from explicitly decoded inputs (or one decoded tile pair at a time), whereas a cold R15 preparation includes the prerequisite decode time.

**Accept is never paused for measurement.** R15 adoption starts at the user accept input timestamp, even if data is cold. It stops at the later of durable adoption-event acknowledgement and the presented frame containing the correct preserved result at the verified target. Present-but-not-durable and durable-but-not-painted states do not stop it. Initial meaningful visible acknowledgement must meet R04 50/100ms and remain labelled pending until authority confirms; it never stops the adoption timer. User think time before the click is excluded. State revalidates the target/document revision at entry and before commit; conflict handling is a separate expected outcome (visible conflict feedback target/ceiling50/100ms after detection under R04), emits no adoption event and never claims successful adoption latency. Explicitly retargeting creates a new user action; the frozen original still determines the preserved candidate.

### Admission, persistence and recovery details

R33 counts well-formed Unicode encoded as UTF-8, not JavaScript UTF-16 units or glyphs. Count logical lines as explicit newline separators+1 after the architecture's recorded line-ending policy; wrap lines do not consume the logical-line cap. Do not normalize or shorten text merely to fit. An invalid surrogate/string or over-limit paste remains a recoverable draft/owned raw import; block its commit, offer explicit reduce/split/cancel, preserve the previously durable text. A completed IME composition is validated as a whole; preedit is tentative, does not emit duplicate history events or a provider request. Correct caret/selection follows grapheme and bidi shaping, not byte offsets. An explicit session Cancel requested during composition is deferred until actual native composition end/cancel settles; then it ends that still-current session and drops pending presentation/Apply intents,without forcing native completion or synthesizing a commit. Escape while composing belongs to native cancellation and is not a session Cancel; a later explicit Cancel outside composition ends the session. EnTextarea remains for independent prompt/description fields only. Synthetic composition fixtures do not prove actual OS IME correctness.

R36's256 semantic elements do not consume or derive from the100-layer cap. The aggregate prompt byte cap wins even if each individual string/element is under its cap. Native document text may remain editable when its complete projection is too large: preserve it, explain the exceeding fields and require an explicit smaller selection/authored caption. Bounds are admission guardrails for app-authored recognized profiles, never Fal token/character limits. Count depth with the root container=1, nested arrays/objects incrementing once. Lexical tokens include each string,number,literal and structural punctuation; stop before allocating an over-limit tree. Detect duplicate decoded keys in each object before ordinary parsing can collapse them, including escape-equivalent keys. Unknown versions/fields/types,plain text,malformed/root-array/double-encoded captions stay separately labelled per API-1.2 E6; do not recursively parse, silently repair, execute markup/URLs or overwrite native objects from a returned caption.
