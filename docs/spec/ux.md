## 1. Product contract and annotated layout

The editor is a local, recoverable image-and-native-text document workspace. An operation is a user choice; attachments are explicit, versioned inputs. Selecting a layer, opening an image, drawing a selection, or retaining a mask never implicitly sends those pixels to a model. A source snapshot can remain attached while its original layer changes; the draft shows “Source captured from revision N; document is now M” and offers Refresh source. Refresh is a deliberate new snapshot and invalidates any dependent mask/resize approval requiring review.

User accepted persistent left request-panel placement on 2026-09-25. Desktop arrangement: tools far left; operation/prompt/explicit inputs/request controls in a persistent left panel; central canvas; layers/properties right; collapsible results/jobs/history below. Responsive drawers remain for narrower windows. This settles placement, not acceptance of the full section. Initial layout uses en-reve tokens, comfortable density and browser rendering:

A pending indicator is not a save receipt. |

At the reference 1440×900 viewport, use nested en-reve split views for canvas/layers and canvas/request panels; the canvas has a usable minimum. Narrow windows collapse one side panel into a named drawer with a persistent opener; do not squeeze controls beyond readable width. At 200% zoom and reflow to 320 CSS pixels, forms/lists become a single scrollable column and canvas remains a deliberate two-dimensional viewport with numeric controls. The visual canvas need not become a linear image, but every surrounding action stays reachable. Initial product target is desktop keyboard/pointer use; touch panning/selection is progressive support, not a promise of mobile Photoshop parity.

DS-1.1 is authoritative for component APIs. Use EnTextarea for prompts; native-backed fields for numbers/selects; EnValidationSummary for errors; EnDialog for confirmations; EnActivityFeed or accessible pages for history; EnTree for labels/selection plus adjacent inspector controls; EnFileUpload for selection only. Upload, decode, durability, source capture, masks and compositing are app-owned. Component en-change/en-input events only update staged drafts after the DS adapter settles; they never prove document or job acceptance. There is one command handler per action. Pending app state is labelled until the durable writer acknowledges it.

### Exact size eligibility disclosure

For active base/text-LoRA custom requests, display endpoint metadata 512–3840 per side in multiples of 16; Instant metadata is 512–2048 in multiples of 16. Dedicated editing auto prose describes input matching at approximately 25MP and ≤8192 per side, with unknown rounding; those are not exact measured provider limits. The nested schema itself permits optional integer width/height with 0 < value ≤14142 and default 512, which does not override stricter app/resource eligibility or prove provider acceptance. Tiling lacks these metadata caps and has no auto; it remains deferred. Presets square_hd, square, portrait_4_3, portrait_16_9, landscape_4_3 and landscape_16_9 are labels, not invented fixed pixel sizes. Request summary separates requested dimensions, app-approved prepared dimensions and actual returned dimensions. No rounding, crop, aspect-ratio change, resize or Large-to-Medium expansion downgrade occurs without explicit review.

## 3. Documents, assets and raster interactions




### Canonical contribution and mask-domain review — CP-1 / F01–F02

The preserved exterior is defined by **canonical document bytes**, not monitor pixels, a JPEG export or provider compliance. Ordinary display composition, source capture, export and replacement use the same retained CP-1 contribution K: layer transform → layer mask → opacity → pinned linear/premultiplied processing and RGBA8 quantization once. Capturing an image or native text layer reads that exact contribution; it does not rebake a higher-precision variant. The stack folds these contributions under the architecture's pinned rules. Empty transparent output is zero; a singleton passes through its exact retained bytes, including hidden RGB. A replacement uses those retained bytes at identity transform, opacity 1 and no reapplied mask. No second mask/opacity/quantization may darken the “unchanged” exterior. In the audit fixture, white at 0.1 opacity yields canonical alpha 26 and canonical value 90 over black before adoption, after adoption and after undo. Native text canonical raster joins this same contract.

The mask editor keeps authored hard coverage H and its effective feather F separately. Feather is the versioned ARCH-1.1 finite triangle filter (radius r in document pixels; r=0 identity, integer offsets with |k|<r, normalized max(0,1−|k|/r), separable product, one R16 quantization; r≤1 is identity). At the document boundary use zero extension without renormalization. Effective support can extend outside the request crop: it is not silently cropped or feathered again.

Before queue admission, upload or provider submission, **Mask extends beyond prepared area** blocks until effective support AND source-to-request/expected-result reconstruction footprints fit the approved domain. Unknown footprints block rather than claiming safety. Show authored edge, feather support, approved crop/padding and safe interior with different patterns plus numeric extents. Initial painted feedback acknowledges validation pending; it is not “queued” or “saved”.

| State/action | User-visible resolution and resulting mask |
| --- | --- |
| Domain review required | Focus error summary with source/crop/radius/footprint explanation. Buttons: Expand prepared area, Clip edit coverage, Change feather/crop, Cancel. Keyboard reaches each option and numeric dimensions. Existing draft/source retained; no upload or paid call. |
| Expand prepared area | Preview larger crop/context padding and request dimensions; recompute both reconstruction footprints. Reapprove any resize, projection and estimate. Keep F unchanged on the document grid, zero outside the document. Old approvals invalidated. |
| Clip edit coverage | Preview lost edit area and potential hard boundary. After explicit approval, M=F within reconstruction-safe interior B and 0 elsewhere; no reblur. An empty M blocks submit with Adjust crop/feather. This is a user-approved change, never an invisible crop. |
| Change radius/crop | Numeric controls and step buttons update cancellable draft preview. Old preview labelled stale until current computation completes; Apply/Generate waits for the current preview and domain validation. Cancel restores last approved values. |
| Actual output differs | Retain output and raw metadata, show actual versus expected size. Block prepare/adopt until a contained reconstruction mapping/explicit clipping is reviewed. Approval cannot invent missing provider pixels or retroactively expand the sampled domain; needing additional pixels requires an explicit new request. |
| Full coverage | If final M covers the whole source crop, warn “This edit can change the whole source crop”; if it covers D, “This edit can change the whole document”. Context padding remains black in provider support mask. |
| Late preview/error | Ignore obsolete preview for acceptance but retain current draft. Error offers retry local preview or revise parameters, with no provider retry. Announce completion once, not each tile or brush move. |

J10/J12 mask and adoption outcomes include these exact cases: for crop [4,8) and r=2, F extends through 3…8 with edge coverage 16384. Identity reconstruction may expand to [3,9) to retain support, or explicitly clip to [4,8) retaining 4…7. Under the recorded 4→2 downsample footprint the safe interior is only 5,6; expanding to [2,10)→4 permits F. Every route uses the verified architecture footprint calculation rather than assuming the nominal crop is safe. M=0 copies full-grid S exactly; original full-grid source beyond request crop is retained. For a captured visible single contribution in its unchanged stack slot, the current-document exterior matches canonical bytes. Hidden/interleaved/additive placements make only their explicitly previewed guarantee.

### Placement preconditions — final architecture cross-read

Retain the full document-grid source contribution beyond the provider request crop. Translate a crop-local authored mask onto that same grid, with zero effective coverage outside its approved support; accepting a cropped result cannot discard the source exterior.

Read-only source capture may include explicitly selected locked or hidden layers. Replacement adoption may not silently hide, change visibility or replace a locked original: offer a new document, or require an explicit prior Unlock command followed by a fresh placement review. For a captured hidden layer, default to a new document or a distinct previewed additive placement; it cannot claim unchanged visible-document exterior. Single-layer current-document exterior preservation requires the source to have been visible and contributing, with its dependency fingerprint and placement preconditions still valid. These constraints apply equally to merged-visible replacement when any affected original is locked.

### Accepted initial document envelope

User-accepted app limits are positive integer document dimensions, at most 8192 per side and 25,000,000 pixels, and at most 100 image plus native text layers combined. They are not provider limits or measured capacity. Native editable text is initial scope (§13); ordinary image contributions use RGBA8 sRGB and Normal source-over. Normal qualification is 2048²/20 layers; stress is 5000²/100 layers with disk-backed tiles. A 1000-row layer metadata fixture tests list behavior; it does not raise the 100-layer document limit. History 10k/100k counts are qualification fixtures, not automatic history truncation. More workload requires a visible limits decision and PERF amendment.

Import static PNG/JPEG/WebP by file picker, file drop or explicit clipboard-image paste. Validate signature/MIME, decode and measured dimensions; normalize orientation and convert to working color with a preview when appearance can change; retain original bytes/profile/orientation. No silent first-frame extraction from animated WebP/APNG/GIF; reject animation with an explanation. SVG/PDF/PSD/PSB/HEIC/TIFF and remote-page/HTML paste are unsupported initial import formats, not automatically rasterized or executed. Clipboard URL/text in a prompt remains text, not an attachment. Unknown or corrupt files retain a failed-import record with Remove/Choose file; they do not create half-valid layers. Mask import accepts a static PNG grayscale/luminance mapping with explicit polarity/alpha handling preview; no guessing.

Output export is PNG with alpha or JPEG with an explicitly previewed matte, quality default 0.9 (app choice), at document resolution unless user approves a separate export resize. Provider output format remains its own request parameter; imported WebP support does not imply WebP model output/export. Working sRGB RGBA8 means no CMYK/spot/HDR/16-bit editing. Picker P3 values must preview their sRGB conversion before applying to raster/matte; DS picker capability does not establish P3 document compositing. Preserve raw provider bytes separately even when normalized working assets differ. Original profiles and conversion version belong to provenance. Transparency checkerboard is a display aid, not exported content.

Native editable text frames are supported initially (§13). Paths/vector artwork, adjustment layers, smart objects, arbitrary blend modes, plugin ecosystem and PSD round trip remain outside scope. Selection polygons are editable mask geometry, not vector artwork. Layer operations: add/import, select/multiselect, rename, reorder, show/hide, lock, duplicate referencing original bytes, translate/scale/rotate via transform, opacity 0–100%, attach/detach a layer mask, create explicit flattened copy of selected/visible layers, delete with undo. Normal blend only. Crop is a reversible document boundary/translation change retaining underlying assets; canvas resize changes bounds, not pixels; image resample creates new derived assets after preview. Inspector Apply commits typed multi-field transforms atomically; pointer drag previews continuously and commits one undoable gesture on release; Escape restores the prior state. Merge creates a new composite and retains originals/history, not destructive asset replacement.

### Result placement and history

Default Accept creates a new named raster layer with explicit placement, or a new document for prompt-only generation when no destination exists. Masked edits use the safe contribution-replacement modes below, not an ordinary extra layer above the source. Before acceptance show placement: new layer in current document, new document at actual output size, or explicit replacement of a selected image-layer version. Replacement is non-destructive: retains old asset/version and is undoable. Prompt-only output on an existing document previews actual size and placement; do not silently resize the canvas or output. User can place at native dimensions, approve fit transform, or choose new document.

Masked-edit acceptance creates an editor-composited candidate: original pixels at zero effective coverage are copied exactly; candidate contributes only in edit coverage with alpha-aware blending. Layering that composite above a still-visible alpha source can double-composite semitransparent pixels: adoption therefore must use architecture’s replacement/visibility grouping so the preview and accepted appearance match once, while originals remain recoverable. The acceptance preview lists any original-layer visibility changes; one undo restores them. Architecture §3.4 defines the exact safe modes (native-overlay restrictions are further explicit in §13): a single-layer source becomes a full document-grid contribution at the same stack slot, identity transform/opacity 1/no reapplied mask, with the original hidden atomically; a complete merged-visible root source becomes a full-document prepared composite with ALL captured visible originals hidden atomically and no original native overlay retained above the root. A source subset below retained native text is not that full-root mode. An arbitrary selected-layer composite defaults to a new document because interleaved stack replacement cannot promise preservation. A distinct additive placement requires its own preview and makes no unchanged-current-document exterior guarantee. The captured dependency fingerprint and document bounds must still match; otherwise placement needs fresh review. No global “keep outside” promise is based on the provider alone.

Results are durable independent candidates even after Discard from the current comparison; “Discard” means not selected for adoption, not permanent byte deletion. Label it “Set aside” in the main UI; explicit Delete candidate opens dependency/undo impact review. Compare at matched document coordinates with side-by-side, keyboard A/B switch, optional difference overlay and zoom sync. Slider reveal has numeric percentage and button alternatives. No generated quality/text correctness is inferred from seed or thumbnails.

Jobs freeze document/target revision and captured stack. Later edits, reorder, target deletion, crop or document resize mark placement “Needs review”; retain candidate and show original target/current document side-by-side. User chooses current-document placement with a fresh preview, restores original context into a new document, or keeps candidate. Never auto-overwrite newer work. ### Draft durability and pending-job undo — architecture alignment

ARCH-1 §§5–6 distinguishes autosaved draft checkpoints from accepted document mutations. Prompt, inspector and dataset drafts checkpoint asynchronously at a proposed ≤1-second active cadence, flushing at semantic boundaries such as blur/Apply/composition end. Show “Draft saving…” versus “Draft saved”; abrupt crash may lose the explicitly unsaved interval. Restore latest draft text, not a fabricated keystroke history; never restore a modal/focus position as if the user had reopened it. When backend authority is unavailable, drafts can remain editable but new document mutations are not labelled saved.

If the user selects a pending-generation intent in History and chooses Undo, explain “Hide this intent and request cancellation; work may still finish”. Its retained job remains in Jobs; no canvas pixels are reverted before adoption. Redo restores intent visibility/eligibility only. If local cancellation prevented dispatch, show “Not run — submit a new request”; redo never submits automatically. Completed results remain candidates requiring explicit adoption. Ordinary adopted-layer undo/redo restores retained assets and visibility, with zero provider calls.

### Save, portability and asset recovery details

Architecture defines the package and transaction format. Required UX distinction: (a) durable local recovery, (b) named checkpoint of a document revision, (c) portable Save copy including owned assets, and (d) flattened raster Export. Portable Save copy uses the proposed .ideogram-project archive defined by ARCH-1 §9.3. Default copy is self-contained: include the full transitive closure of the chosen document/history/checkpoints, associated jobs and every nondeleted retained candidate, owned source/mask/working/result assets, draft/preferences checkpoint, and referenced adapter/dataset lineage/artifacts. The scope preview lists included bulk content and excludes unrelated documents/unreferenced datasets. Missing required bytes block a successful self-contained copy; an explicitly labelled incomplete recovery package is a separate choice, never presented as complete. Candidate retention in local storage remains independent of whether a portable copy includes unrelated library content. Server-prepared bundle bytes show “Copy ready”; “Saved to destination” requires the browser/OS destination-write acknowledgement. A mere download request is not proof of that write. Save/reopen preserves operation drafts, source bindings, result dispositions and provenance according to the manifest; provider transport secrets are excluded.

Open a portable copy as a new local document identity to avoid conflicting live writers; preserve origin identity/provenance. Imported job records are historical references, not executable outbox entries. “Reconnect original local job” requires matching durable local identity, not trusting a copied URL. Restore/relink verifies expected content hash; a different file is a new version that triggers source/mask review. A filename match alone cannot satisfy missing-asset recovery.

Document list shows last saved checkpoint, locally recovered newer edits and missing assets separately. Recovery preview names the last durable sequence and any unsaved draft. Disk-full/read-only failures leave the last accepted document intact, retain the current draft if memory permits, stop new jobs/imports, and offer Save copy to another approved location, storage review or retry after space is freed. Never advertise a failed append as saved.

### Honest job state machine

| State | Visible message and permitted actions |
| --- | --- |
| Draft / invalid | Editable prompt/attachments/settings; validation summary links fields; no job exists. Disabled submission reason is visible, with an enabled Review issues action. |
| Preparing assets / resize pending | “Preparing source…” or “Approve request resize”; meaningful progress counts/bytes only when known. Cancel preparation returns intact draft. Request-size approval invalidates when relevant source/mask/size changes. |
| Accepting locally | “Saving request…”; submission button deduplicated; draft retained. Only durable receipt becomes Queued locally. |
| Queued locally | Display local order and reason (one active request, paused, storage, account qualification). Move up/down and cancel waiting job are explicit commands; do not mutate frozen payload. Edit creates a replacement draft and cancels old queued intent explicitly. |
| Submitting | “Sending request…”; local attempt ID visible in details. Closing/disconnect does not imply rejection. |
| Submission uncertain | “We could not confirm whether the service accepted this request.” Reconcile original identifiers first; Check again/Inspect details/Keep waiting. If still unknown, “Create another attempt” confirmation states duplicate work/charges may occur, shows frozen request and unknown cost. Never auto-resubmit. |
| Provider queued / running | Provider status and elapsed time; queue position if present labelled count ahead, not ETA. “Running” is not a numerical percentage. Inspect/cancel-request actions; user can keep editing. |
| Cancel requested | “Cancellation requested; work may still finish.” Pending paint, durable cancel intent and eligible dispatch are separate. A stop button does not guarantee provider cessation/refund. |
| Canceled before submission | Confirm local queue removal; no provider call. Draft may be restored. |
| Provider cancellation confirmed | Terminal record with evidence; any later conflicting completion goes to reconciliation, not deletion. |
| Provider completed, retrieving | Completion may represent an error; fetch/validate/download before Ready. “Retrieving 2 of 4” or bytes if total known. |
| Candidate preparation | Decode, inspect and preservation-composite preparation; actual returned dimensions shown; per-candidate failure does not hide successful siblings. |
| Ready / partial | Individual candidates Ready/Unavailable/Blocked/Metadata incomplete. “2 ready, 1 failed, 1 missing” rather than complete success. No automatic retry for missing images. |
| Late result | “Result arrived after cancellation / from an earlier document revision.” Retain durable candidate, notify once, require deliberate placement. |
| Failed / expired | Distinguish input, access, capacity, server, download/decode, storage and expired-file causes; keep request/provenance. Retry download of same output where possible; rerunning model is explicitly a new attempt. |

App concurrency starts at one active request, counted from submission until terminal provider reconciliation, across tabs and inference/training. A request’s count 1–4 is a batch, not concurrency. Preferences displays “1 active request” and qualifying requirements for raising it: account allocation plus local workload/resource qualification; no arbitrary higher selector that silently assumes capacity. Queued jobs retain original order except deliberate reorder; pauses and reservations are visible. At 1000 pending entries, preserve draft and ask the user to manage the queue; no eviction. Unknown submissions retain their capacity reservation until reconciled or explicitly resolved under architecture’s duplicate-risk policy. Training initially shares the single active slot.

Estimate summary always labels “Estimate” or “Known subtotal; other fees unknown”. Show endpoint, count, dimensions, tier, rate source date/identity and assumptions. When exact size/billing unit or expansion/batch/cancel fees are unresolved, do not manufacture a precise total or guaranteed upper bound. Show the known rate and unresolved items, or “Estimate unavailable”. Documented trainer steps × rate can be a labelled subtotal. Actual charge appears only from provider-reported usage/billing evidence, otherwise “Actual charge unavailable”; $0 stream metadata is not free usage. User’s eventual submit is an explicit request for the displayed operation, not approval of a hidden pipeline.

### Results and metadata integrity

Inference response requires images, prompt, seed, timings and has_nsfw_concepts. Store the exact returned prompt separately from typed and submitted prompt; “Use returned prompt” copies it only on request. Store exact seed without lossy numeric conversion; “Use this seed” fills a new draft. Display arbitrary timings by key with “Unit not documented” unless known; queue metrics.inference_time is seconds, separately labelled. Never infer wall-clock cost or throughput from timing fields.

Optional ImageFile content_type/file_name/file_size/width/height can be absent or null. Derive actual MIME/dimensions/bytes from validated downloaded data, label Derived versus Provider, and use a safe local display name if absent. Conflicting declared/measured dimensions or MIME produce a visible integrity warning and block acceptance pending inspection. URL is transport, not identity; owned content hash identifies the candidate. If all images fail download, result stays “Output unavailable”, not succeeded.

Required metadata missing means malformed/incomplete provider response, not optional absence. Preserve safe downloaded assets and diagnostics; show “Metadata incomplete” and do not silently treat it as a normal ready result. Safety flags true yield a labelled blocked/withheld candidate according to app policy; false is a provider observation, not safety certification. Missing/misaligned flag counts yield “Safety status unknown”, no automatic display/adoption/export; retain diagnostic evidence and offer reconciliation/support. Do not guess a per-image flag mapping without a valid correspondence. Empty images or fewer images than requested are explicit empty/partial outcomes; an extra image is retained for inspection rather than silently applied. Unknown fields are retained in sanitized provenance, not rendered as executable HTML.

Credential errors show “Local service needs configuration” with server-side setup guidance; no FAL_KEY field in document or browser history. Missing local service retains local UI/drafts but disables commands requiring authority. 401/403, 422, 429, 5xx, non-JSON failures, expired URLs and offline states have distinct messages/actions. 422 links named request fields where possible; 429 pauses dispatch/rechecks capacity; known status polling can retry with backoff; an uncertain submission cannot use the same retry loop. Errors never dump secret headers/signed URL tokens into the UI.

### Retention and cleanup

Keep unused candidates until explicit deletion. Library storage view lists document assets, candidates, adapters/datasets and derived caches separately with byte totals when known. Dependency inspector shows which document/checkpoints/undo paths/jobs reference an asset. “Free preview cache” is safe, reversible recomputation; “Delete selected candidates” requires explicit selection and dependency review. Referenced original/adopted assets cannot be purged through generic unused cleanup. A destructive history-prune feature is outside initial scope; do not silently disable undo to free space.

PERF-8 admission rules: show warning at 80% target/by 85% used; refuse new allocations at 90% or when predicted bytes plus reservation overhead and 1GiB cannot fit. Unknown sizes reserve conservatively; this is an app safeguard, not a provider limit. Active downloads encountering pressure pause/recover when supported or leave explicit partial/failed artifact; never claim resumability without validated range/identity support. Retention applies to owned bytes, not forever-valid provider URLs. User may back up and delete a whole document with an explicit list of retained/shared assets; shared library assets remain until their own explicit deletion.

During composition, keep the caret and IME candidate UI stable; do not replace the native value or intercept key events. Intermediate characters may preview but never commit document mutations, update bound semantic fields as durable facts or dispatch a job. External document change invalidates the draft’s expected revision and opens a non-destructive conflict review; it does not overwrite current composing text. On connection loss, keep the text draft and distinguish “Draft not saved” from the last durable text layer. ### Connected native editor, selection and view switching — F05 correction

Both anchored-card and inspector presentations use the **same app-owned HTMLTextAreaElement, same connected host, same draft model and same session identity**. Change layout/presentation attributes on a stable editor region; do not relocate the node through disconnect/reconnect, clone it, replace it with EnTextarea, remount it behind a conditional template, or create a hidden second editor. One visible label remains associated with that control. The requested presentation changes where the editor is shown, not the authoritative text, typography or selection.

Outside composition, record native `selectionStart`, `selectionEnd`, `selectionDirection` and scroll offsets before an explicit presentation change. Keep the same value and control identity. If focus temporarily moves to the switch button, return focus to that same textarea with the same range via its native `setSelectionRange(start,end,direction)`; preserve forward/backward orientation, not merely a caret or select-all. Restore scroll after layout without changing text. If focus has deliberately moved elsewhere while layout is pending, do not steal it back. Any range restore is tied to the same draft generation/value; a stale callback must not apply old offsets to a newer edit. Native selection and layout cluster mapping remain distinct; no private shadow DOM, component property injection or synthetic select-all substitutes for arbitrary selection.

During IME, leave the connected control, native value, selection, focus and candidate window alone. A presentation request becomes a labelled **Switch after composition** pending UI intent; coalesce to the last requested presentation and offer Cancel switch. Do not consume native IME keys to force the switch or forcibly call blur/endComposition. On genuine compositionend, settle/deduplicate the final native input, then apply the latest still-valid presentation request with current native range. Compositionend updates the recoverable draft only; it is not Text Apply. External revision conflict cancels stale switch callbacks and retains draft/conflict recovery. If a responsive layout cannot fit the card during composition, keep a scrollable stable editor region until composition settles instead of removing the control.

Cancel switch clears only the presentation intent; text/range and composing state remain. Cancel text edit during active composition is a deferred cancellation intent: preserve the native session until the native composition ends or the user dismisses it through normal platform behavior, then discard the layer draft explicitly, clear any pending switch, restore the prior accepted canvas and return focus to the surviving Text layer Edit trigger (or Layers region if deleted). Escape used by IME is not also Cancel draft. No accepted document mutation, undo entry, source capture or model request occurs from switch, focus restoration, cancel, blur or responsive rearrangement. Explicit Apply retains the existing prepared-render/durable transaction contract; it cannot be synthesized by a pending switch or input callback.

Keyboard paths: Edit Text → textarea → local Apply/Cancel/Switch controls → typography fields in documented logical order. The same named editor region stays in the accessibility tree and DOM reading order in both presentations; the presentation switch announces “Text editor in inspector” or “Text editor by canvas” once after completion. Switch/cancel returns to the same control or named initiating trigger, never an arbitrary canvas pixel. Native arrows, Shift/word selection, clipboard and local undo remain available. Composition, selection direction and focus behavior need later physical browser/AT/IME qualification; this correction is a public-API-compatible specification, not a runtime pass.

### Final architecture cross-read details — ARCH-1.4 §16

Read the saved ARCH-1.4 §16 on 2026-09-25. Initial tracking, user language/OpenType, variable-axis and synthetic style controls remain deferred.

Unicode source remains unnormalized. Native editor stores LF newlines; CR/CRLF import conversion is explicit and original bytes remain provenance. Native caret offsets and layout clusters use architecture’s versioned mappings; the inspector exposes readable text, not internal glyph indices. Auto direction uses first strong character per paragraph with recorded LTR fallback when no strong character exists. Fixed-frame overflow clips appearance while retaining all text; it does not silently remove lines.

Native-overlay current-document replacement requires exactly ONE original canonical K at its exact slot, with all other original K/order/dependencies unchanged; a contiguous multilayer source block is NOT eligible.
