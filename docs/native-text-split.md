# Native text admission and reviewed splitting

This implementation note maps [UX R33](spec/ux.md) (the native-text row), TX05 in [testing.md](spec/testing.md), and the native text/history contracts in [architecture.md](spec/architecture.md) and [api.md](spec/api.md). It supplements those reviewed specifications; it does not change their frozen snapshots or claim measured performance, physical IME, or native qualification.

The connected native textarea retains the complete draft. The inspector counts UTF-8 bytes, LF-delimited logical lines, and Unicode scalars separately. Invalid scalar sequences are labelled invalid instead of being counted as valid UTF-8. Current-document text usage is read from bounded source metadata for the exact document revision and image identity. Projected usage subtracts the replaced layer's original text and adds the complete draft. Unknown usage blocks adoption until verified. The accepted bounds remain 16 KiB and 256 logical lines per layer, 1 MiB of current native text per document, and 100 combined image and text layers.

`Review split into layers` is an explicit action. It does not modify the draft or document. The proposed partition prefers LF boundaries; if that wastes the available layer slots, it packs at extended-grapheme boundaries. Ordered UTF-8 ranges concatenate to the original bytes exactly, including trailing LF, BOM, combining characters and bidi controls. No normalization or synthetic separator is introduced. An indivisible grapheme exceeding a layer limit refuses with the original draft retained. Browser and server use their actual `Intl.Segmenter` implementations, not a claimed replacement for the pinned native shaper; the server independently recomputes the partition and refuses any disagreement.

Each part uses the saved draft's exact style, font order and frame. The user reviews an actual native layout, confirms that part, and then previews the next. Only one pixel preview is retained. Durable preparation recomputes the confirmed layout and checks its raster and dependency identities. Candidate metadata is bounded; the plan is at most 64 KiB and contains at most 100 parts. Editing the draft invalidates the review. Cancel split review keeps the full draft available for native Copy/edit. Failed preparation, stale authority, or rejected adoption does not partially change the document.

The explicit `SplitTextDraft` history command carries the saved draft fence, the existing layer/version or a new-layer indication, the staged plan reference, and its reviewed hash. The writer validates complete saved text, exact ordered ranges, every candidate's token/text/style/frame/fonts/layout/raster, and current document/layer ownership. Browser text preparation and its realm admission are fully released before serial server verification; no independent per-part budget or final-part admission is borrowed for siblings. The writer rechecks the original authority and aggregate limits at commit.

For an existing layer, the first part retains its ID and advances its version. New siblings follow it at the same stack position. Visibility, opacity, blend, and the document-space mask are inherited; reviewed local offsets compose with the existing affine transform. Composition bindings are not silently rewritten: the advanced version makes prior reviewed bindings stale, and the siblings are unbound. New text starts at the saved placement. Off-canvas positions, overlap, masks and opacity can change the combined appearance; the per-part layout previews do not claim old-pixel equivalence.

All accepted parts, their composite, one history node, and one document revision are registered in the existing atomic writer transaction. One Undo restores the before-state. Unpublished intermediate raster assets remain internal to preparation. The original saved draft and reviewed plan are retained through existing command-owned object roots; the history-node root format is unchanged.

An existing returned-description origin remains shared by its edited/split descendants. A new described split uses the typed `created-text-split-description-1` origin, binding the bounded saved-draft JSON and exact reviewed plan, with the full text in a separate blob. This does not invent an over-limit accepted TextVersion or widen the legacy single-layer description format. Retention and portable-copy traversal validate the full draft, selection, ranges, candidates and immutable source dependencies. Archival candidate/session tokens are provenance only: reopening or copying a plan does not restore live draft, session or command authority.

The current protocol admits the new history operation. Frozen legacy operation lists and schema-18 capabilities remain unchanged, so an older reader must refuse the unsupported history rather than claim compatibility. Current profile metadata is generated only by the official text-profile producer after the implementation sources are placed; the exact predecessor remains supported through the existing retained-profile path.

The functional prior-reader regression compiles the exact pre-split schema-19 executable from its declared historical source input, opens an unchanged schema-19 baseline, and checks unsupported split-event refusal with transactional state preservation. This is separate from physical/native rollback qualification. The container input packet must be refreshed by its normal producer for that added historical input; an older packet cannot be relabelled as current.
