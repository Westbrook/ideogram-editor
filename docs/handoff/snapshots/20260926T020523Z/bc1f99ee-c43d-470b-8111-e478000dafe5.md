- Replay MUST issue zero provider requests and use recorded assets/outcomes. Capture random/time/ID inputs; a seed is provenance, not a guarantee of future pixel identity. Distinguish replay, redo and an explicit new generation.
- Separate request acceptance, provider completion, durable result import and document adoption. Define undo/redo/branching and late success after cancellation, edited/deleted targets, duplicate/out-of-order notifications and partial batches. Late/stale results must not silently overwrite current state; specify recoverable result handling.

Separate provider credentials from app authentication; define missing-key behavior, same-origin routes, validation/redaction, upload staging and accessible asset URLs.

Separate local/SDK/provider retries and do not promise exactly-once remote execution without evidence. Use local polling/reconciliation; deployed webhooks have separate reachability/verification requirements.
- Retain source/mask/result/weights/config bytes by durable identity outside event payloads. Define download failures, URL expiry, asset retention/garbage collection respecting history, snapshots/compaction/schema migrations and storage-exhaustion recovery.
- Cover versioned training datasets/captions/config, long-job recovery, adapter lineage/format compatibility and artifact retention. Include instrumentation and memory/replay consequences tied to Task 6.
