# Accepted operation compatibility — v1
Status: routing policy accepted by the user on 2026-09-25. Provider evidence corrected later that day after catalog discovery; see the evidence addendum below. The original six-endpoint set was incomplete. Dedicated image-to-image and inpaint LoRA routes supersede the former source/mask+LoRA gap. These are factual corrections within the authorized full-family research, not newly inferred user approvals. Candidate workflows and unverified behavior retain their labels.

Accepted policy: the user chooses an operation and explicitly attaches its inputs; the editor selects a compatible endpoint. An image or mask merely present in the document does not become request context automatically. Speed preferences never justify dropping required context.

## Direct operations
All endpoint suffixes below are relative to ideogram/v4. All inference operations require a prompt.

| User operation | Required operation inputs | Endpoint | Compatibility |
| --- | --- | --- | --- |
| Generate image | Prompt | base | No source image, mask or adapters in the request |
| Generate with Instant | Prompt | /instant | No source, mask or adapters; no rendering_speed or acceleration; expansion None/Medium only |
| Transform image / make image-based variations | Prompt + one source image | /image-to-image | strength 0–1; no mask or adapters |
| Edit masked region | Prompt + one source image + mask | /inpaint | strength 0–1; no adapters; white regenerates, black preserves |
| Generate with adapters | Prompt + selected V4 LoRA adapter(s) | /lora | Up to three adapters, each scale 0–4; no source image or mask |
| Transform image with adapters | Prompt + one source + selected V4 adapters | /image-to-image/lora | Source and adapters accepted together; up to three adapters |
| Edit masked region with adapters | Prompt + one source + mask + selected V4 adapters | /inpaint/lora | Source, mask and adapters accepted together; up to three adapters |
| Train adapter (later phase) | Training archive with images and caption handling | /trainer | Separate dataset/training controls; yields adapter and configuration files, not an edited image |

For Generate with adapters, requiring at least one selected adapter is accepted UX policy. The provider schema itself permits an empty adapter list. Multiple selected document layers can become ONE source raster only through an explicit compositing operation; that does not imply independent multi-reference conditioning.

## Endpoint-specific control differences
| Control | Base / LoRA | Instant | Image-to-image / inpaint |
| --- | --- | --- | --- |
| Rendering speed | TURBO / BALANCED / QUALITY | Not exposed | TURBO / BALANCED / QUALITY |
| Acceleration | none / low / regular / high | Not exposed | none / low / regular / high |
| Prompt expansion | None / Medium / Large | None / Medium | None / Medium / Large |
| Size | Preset/custom; default square_hd | Preset/custom; default square_hd | Preset/custom/auto; default auto |
| Source strength | Not applicable | Not applicable | 0–1; defaults 0.8 / 1 respectively |

Base/LoRA x-fal size metadata specifies 512–3840 per side in multiples of 16; Instant specifies 512–2048. Image editing describes auto as matching input size with an approximately 25MP, 8192-per-side cap. Generic schema bounds differ from endpoint metadata, so these must remain source-labelled constraints pending runtime verification. Switching models never silently resizes an image or replaces Large expansion with Medium.
The five initially documented inference endpoints also expose num_images (1–4), seed, output_format (jpeg/png), sync_mode and enable_safety_checker. Transport and account-policy fields need not be ordinary creative controls. The trainer has its own steps, resolution, learning rate, captions and output-format settings.

## Conflicts and capability gaps
| Requested combination/operation | Accepted handling |
| --- | --- |
| Source or mask + Instant | Explain that Instant does not accept these inputs. Offer the compatible editing endpoint, optionally with TURBO. Do not switch silently. |
| Source + LoRA | Route Transform image with adapters to /image-to-image/lora after endpoint-specific validation; this dedicated route supersedes the original verified-set gap. |
| Source + mask + LoRA | Route Edit masked region with adapters to /inpaint/lora after endpoint-specific validation. A staged workflow is not required merely to combine these inputs. |
| Mask without source | Require source selection; do not submit. |
| Multiple independent reference images | No matching reference-list field in the verified inference schemas. Offer selecting one source or an explicitly previewed composite, without claiming equivalent conditioning. |
| Extend canvas / outpaint | Candidate app workflow: pad source, mask new area, then inpaint. Needs validation of seams, sizing and preservation before being presented as supported. |
| Upscale | No dedicated upscale operation in the verified V4 set. Keep as an explicit capability gap; any adjacent-model option requires a separate scope decision. |
| Negative prompt / native style preset / palette | No dedicated fields in the checked V4 inference schemas. Prompt-writing aids may be offered as app features, clearly labelled. |
| Re-run / variations | Repeat the selected eligible operation with explicit prompt, seed or strength changes. Preserve provenance; do not promise pixel identity from a seed. |

## Accepted routing rules
1. Preserve explicit user operation and attachments.
2. Validate the complete candidate payload, including field differences and unsupported combinations.
3. Display the resolved operation/model, actual inputs and proposed conversions.
4. Resolve conflicts before submission; never silently drop inputs or choose an older model.
5. Freeze source/mask/adapter versions and settings at submission. Later document changes cannot retarget an in-flight job.
6. Keep incompatible drafts and per-operation settings, while excluding inactive settings from the validated request.
