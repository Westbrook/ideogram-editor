## Ideogram v4.5 model amendment — 2026-09-30

**Decision:** prefer v4.5 for new generation and non-LoRA editing once its contracts are integrated and qualified. Retain explicit v4 choices wherever v4.5 lacks a verified equivalent. Model changes never silently reroute an existing draft, queued job, retry or retained history. This is a plan change, not evidence that the newer model is faster, produces better results for this editor, or is production-ready.

The review used fal's official [generation API](https://fal.ai/models/ideogram/v4.5/api), [generation schema](https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=ideogram/v4.5), [generation guide/pricing](https://fal.ai/models/ideogram/v4.5/llms.txt), [edit schema](https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=ideogram/v4.5/edit) and [edit guide/pricing](https://fal.ai/models/ideogram/v4.5/edit/llms.txt). The model page's published metadata exposed the edit route, which was then checked directly. Evidence is published schema/prose only; no inference, upload, billing, cancellation or quality experiment was performed. Unverified capability means absent from this inspected contract set, not proof that no private or future endpoint exists.

### Contract changes required by the plan

| Area | Verified v4.5 difference and planned treatment |
| --- | --- |
| Request fields | Both routes: `prompt` is 1–10,000 characters; `num_images` is 1–8 (default 1); nullable integer seed is optional; `sync_mode` defaults false; `additionalProperties: false`. Generation adds `quality: low/medium/high` (default `medium`) and boolean `enable_prompt_expansion` (default true). Edit quality/precision constraints are discussed below. Keep the app's existing 1–4 count limit initially and the first live milestone at one image; 5–8 is a later explicit queue/resource scope change. |
| Unsupported v4 controls | Do not send `expansion_model`, `rendering_speed`, `acceleration`, `output_format`, `enable_safety_checker`, or editing `strength` to these v4.5 routes. Preserve values in the originating draft and require an explicit operation/setting choice. Generation's boolean expansion is not an alias for v4 Medium/Large. Edit always prepares structured instructions and has no declared expansion toggle. |
| Generation sizes | Use the published 36-size allowlist, not v4's generic multiples-of-16 rule. `square` becomes 1024×1024; 4:3 presets are 1152×864/864×1152 and 16:9 presets are 1280×720/720×1280. Default is `square_hd`. Preview any change from an existing draft; nested ImageSize defaults do not override the route's explicit size list. |
| Edit geometry | Default `auto` follows source geometry but may be downscaled by the provider. Only **unmasked regular** edits accept custom/preset sizes; custom dimensions are ≥256, multiples of 32, area ≤4,194,304 pixels, ratio ≤6:1. Edit presets use their own standard fal dimensions; do not copy generation's remapped preset dimensions. Masked or high-precision edits use auto. Show requested, prepared and actual returned geometry; validate mapping and block unsafe adoption instead of silently resizing the document. Provider downscale thresholds remain unqualified. |
| Mask semantics | v4.5 requires equal source/mask dimensions, **black edits / white preserves**, and both regions after rounding. Keep the editor's canonical white-edit/black-keep mask and invert only the v4.5 transport representation. Preserve the original R16 mask; review transport thresholding, crop/padding/halo and exact geometry. Reject all-edit/all-keep masks on this route and offer an explicitly selected unmasked operation where appropriate. Never reuse v4 mask bytes unchanged. |
| Preservation | Keep existing app-owned exterior restoration, candidate comparison, provenance, safe adoption and undo/redo. Test high precision's unchanged-pixel restoration independently, including returned-size changes; do not remove the application's preservation contract based on provider prose. |
| Reference limits | Schema allows at most four references; prose lowers this to three with a mask. Enforce the cross-field rule before review/dispatch. Upload/privacy review must name every transmitted image. Source formats/byte limits and reference semantics need endpoint-specific confirmation; do not import V3's 10 MB rule. |
| Results and safety | Both routes require only `images: File[]` and `seed`. They do not declare v4's result `prompt`, `timings`, `has_nsfw_concepts`, or ImageFile dimensions. Plan a versioned result adapter; derive dimensions/type from validated bytes and record missing provider metadata as unavailable. Never synthesize an expanded prompt or “safe” result. Preserve existing safety policy; explicit policy reconciliation is required before admission of this profile. |
| Composition and format | Revalidate the v4 structured-caption serializer against v4.5 rather than assuming JSON prompt semantics carry over. Preserve app-native editable text. Output format is provider-controlled in these schemas; validate actual bytes, and keep any local export/conversion choice distinct from provider output settings. |
| Queue, privacy and history | Use the documented queue flow. Requalify endpoint routing, result/error envelopes, credential-free media fetches, partner processing/retention, cancellation, uncertain holds and exact retry identity. `sync_mode` alone is not a zero-retention promise. Keep V4 historical evidence and requests bound to their original endpoint/profile; never auto-fallback across versions or transfer old live-call authorization. |
