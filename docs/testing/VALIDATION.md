Asynchronous source, dependency, output and reuse hashing preserve deterministic manifests while allowing the evidence monitor to observe finalization. A reuse entry must also bind a matching retained receipt, successful sealed log and verified originating evidence audit.

Normal Node tests execute on each invocation. Explicit `--resume` can reuse an unchanged successful Node gate and its verified TAP log from a source-stable development receipt. Gates with browser/fixture/completion/adapter preparation, including authentic schema18 migration installation, execute again. An old failure receipt is never edited into a pass. Browser test outcomes, physical samples and qualification receipts are never reused as new execution. `--fresh` disables development reuse.

Immutable browser fixture paths are separate from evidence paths (`TEXT_APP`, `IE_RECOVERY_APP`, `IE_RASTER_APP`). The developer campaign bridge retains and checks preparation manifests across its focused/full stages. Each editor spec has an evidence namespace in a batch; mutable browser contexts stay isolated. Chromium/Firefox can share a worker browser process in the three custom editor fixtures; WebKit persistent profiles remain per-test. The managed text renderer retains its existing navigation/reload and stock-native storage boundaries; this integration adopts the reviewed fixture-path/configuration joins. The donor's separate navigation-consolidation observations are historical and do not authorize deleting those managed assertions or fixture interactions.

Keep healthy installs, browser distributions and owned workspaces. Keep deliberately cold installs cold. Do not clean away a leak, failed snapshot or contaminated database that a test is intended to detect. End owned services at the documented batch boundary. No automatic workspace/evidence deletion is introduced.
