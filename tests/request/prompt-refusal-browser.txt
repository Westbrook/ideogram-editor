Source-only authored browser cases. No runtime qualification is claimed until
the root-owned gates execute the complete assembled source tree.

Use the repository-pinned Node 26.10.0, npm 12.1.0, Playwright 1.63.0 and its
matching Chromium, Firefox and WebKit installations. Do not install a different
browser revision to make a gate pass. All output defaults to ignored artifacts.

From the repository root, with the pinned toolchain selected and an explicit
evidence allocation covering a fresh output leaf, use the shared runner:

  export IE_EVIDENCE_ALLOCATION=/absolute/path/to/evidence-allocation.json
  npm run validate -- run --groups preflight --browsers all --browser-groups request-prompt-refusal --output /absolute/path/to/allocated/fresh-run

The worker owns a Vite server on literal IPv4 127.0.0.1 with port0, strictPort
and HMR disabled. It awaits listen, validates the actual bound TCP address, and
uses only that exact origin for navigation and the existing network refusal
check. Each worker cache stays below its allocated project output; finally
awaits owned server close. No fixed port is probed/reused by this fixture and no
foreign process is stopped. Pinned Vite internally probes ephemeral candidates
then binds the selected port. That final bind can still race and fails closed;
the fixture adds no probe, retry, or server reuse.
REQUEST_PROMPT_SOURCE_ROOT may select the complete assembled source tree; the
shared runner supplies REQUEST_PROMPT_BROWSER_OUTPUT for each engine. The selected
source tree must contain
the complete effective src graph, including request-prompt-memory.ts. It is not
a correction overlay; every product import and the fixture ledger use that one
tree. The repository's installed frozen public En Reve packages are unchanged.

Five cases run in each browser. They use the actual RequestEditing and child
controllers, real allocationLedger reservations, and public scoped/global En
Reve registration. Native controls are located by accessible role and label.
Assertions inspect standard HTMLTextAreaElement properties, public events,
fixture persistence observations, and exact owner cleanup.

The editor's session/persistence/command boundary is a deterministic fake. It
tracks registered draft identity, accepted wire snapshots and refused saves,
without writing a server or making provider calls. Pressure and observations
exist only in the test entry. This suite is not durability, network security,
whole-product accessibility, native undo memory, JS heap or process RSS proof.

The final case explicitly uses synthetic compositionstart/beforeinput/input/
compositionend sequencing and a direct native value write to model an admitted
exception: a noncancelable edit exceeding the prospective input reservation.
It proves guard/retention/retry behavior in real native DOM; it does not qualify
physical IME, dictation, autofill, or assistive-technology editing workflows.
