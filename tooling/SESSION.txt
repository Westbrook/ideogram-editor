LOCAL SESSION BOUNDARY — LP-1 / LS-1 (P1a browser integration)

Use the qualified toolchain from tooling/README.txt, from the repository root:

  export PATH="$PWD/.toolchain/bin:$PATH"
  npm run typecheck
  npm run build
  npm run test:session
  npm start

npm start launches the compiled server and durable writer. The OS application-data
root and deliberate legacy-root selection are documented in tooling/STORE.txt.
It creates new private directories with mode0700, binds only127.0.0.1 at an OS-selected port, and writes the nonsecret
origin/pid/time to root/launch.json (0600), and opens a five-minute pairing link
through the OS browser launcher. The URL fragment is never printed. Type pair
and Enter in that same terminal to open a new one-use link. Ctrl-C stops the
server and invalidates every session/token. No provider key is required.

Explicit root/headless startup (replace the path with a new absolute directory):

  npm start -- --root /absolute/private/editor-root --no-open

Existing roots must be owner-owned and exactly 0700. Existing launch.json must
be owner-owned, a single-link regular file, and 0600. Symlinks in roots or path
components are rejected; there is no automatic chmod of user files. On macOS,
/var is a symlink: use an actual canonical path such as /private/var/... if
creating a temporary root. This slice supports POSIX permissions; Windows ACL
qualification is unavailable and startup fails closed on Windows.

npm start now serves dist/app from the production app build by default.
The browser shell supports local drafts and session controls; document editing
and provider dispatch remain unavailable. See tooling/SHELL.txt. To override
with a trusted browser build, with index.html and hashed JS/CSS/font/raster assets:

  npm run build:server
  npm start -- --root /absolute/private/editor-root --static /absolute/build/app

The build directory must be separate from the storage root, with no symbolic
links, and contain an HTML head. It is snapshotted at startup; rebuild and
restart to pick up changes. GET / serves index.html with the pairing prelude.
Built JS/CSS/fonts/rasters are served by exact path. Other HTML, SVG, source maps,
dotfiles, arbitrary paths and private storage are never served. Use / as the
shell entry; /index.html is not another route. Do not use this option for a user
asset directory, repository root, or untrusted project/archive content.

Development uses this SAME secured listener for static files and /api, including
the exact recorded Host/Origin and all security headers. npm run dev builds the
production browser app and server, then launches it; pass launcher options with npm start after building.
No Vite dev listener, proxy, websocket, HMR, port override, origin alias, CORS or
forwarded-header exception is supported. The shell owner should build its Vite
production output and restart this listener while integrating. This deliberate
single-origin arrangement avoids the proposed proxy; adding a proxy later
requires its exact separate server-held credential and Q26 verification.
The independent public-consumer fixture still owns its separate Vite config,
build:consumer, typecheck:consumer, test:browser and test:consumer commands.
Never proxy the editor's session API through that qualification fixture.

BROWSER INTEGRATION CONTRACT

The server injects a fixed inline prelude as the first element of <head>, with
its exact SHA-256 permitted by CSP. It synchronously captures #pairing=<token>,
removes the pairing fragment with history.replaceState before any shell
resource requests. Only exact #request/#canvas/#inspector/#results navigation
fragments are retained; all other fragments are discarded. Trusted build
resource tags are placed in an inert template to defeat speculative preloading,
then activated after cleanup (styles before application modules). The prelude and places the valid 43-character token in a configurable,
nonenumerable window.__IE_PAIRING__ property. A malformed pairing fragment is removed
and yields undefined. Same-tab fresh pairing links run the same cleanup and
notify the shell through a secret-free ie-pairing event. The prelude preserves pathname, query and history.state.
Do not move scripts/resources before this prelude or add a competing fragment
bootstrap. The shell's first startup step is:

  const pairingToken = window.__IE_PAIRING__;
  delete window.__IE_PAIRING__;

Keep that token and the returned CSRF token only in memory.
The CSP style-src-attr permits only SHA-256 hashes of the two fixed initial
en-reve splitter style strings (--en-split-ratio:0.24; and 0.73;). Keyboard
resizing uses CSSOM. Arbitrary inline styles/scripts/handlers remain blocked. Never log/store
them or place them in URL/query, DOM attributes, localStorage, sessionStorage,
event/provenance data or a downloadable bundle. No provider-key input exists.
When a token is present, POST /api/v1/session/bootstrap with exactly:
  { protocolVersion: 1, pairingToken }
When no token is present, GET /api/v1/session to resume an existing cookie.
Use fetch with credentials:'same-origin', redirect:'error', cache:'no-store'.
Set Content-Type:application/json for mutation controls and X-App-Client:LP-1
for JSON reads. Browser-controlled Origin and Sec-Fetch-* headers must be left
to the browser. Mutations require its exact Origin; reads without Origin also
require Sec-Fetch-Site:same-origin and X-App-Client:LP-1. Cross-site/same-site API calls,
null/foreign Origin, navigation/image JSON reads and all forwarded headers fail.

POST /api/v1/session/renew and POST /api/v1/session/revoke take exactly
{ protocolVersion: 1 } plus X-App-CSRF. Renew rotates cookie and CSRF, preserves
clientId and the original twelve-hour absolute expiry, and refreshes the
thirty-minute idle deadline. Successful reads refresh idle. Revoke returns204
with no body. Missing/expired credentials require a fresh local pairing link.
Never automatically retry a lost renewal/revoke response: GET /session first,
then use its current CSRF or request local re-pairing on401. Old CSRF/cookie fail
immediately, including concurrent requests that finish reading their body later.
One-use pairing expires at exactly five minutes, idle at thirty minutes, and
absolute lifetime at twelve hours. Restart/root replacement invalidates all.

Session/capabilities wire types are in src/protocol/session.ts (browser-safe).
Actual errors use LP-1 LocalError: protocolVersion/requestId/error, fixed safe
code/message/retry, and inline supportedVersions:[1] for426 PROTOCOL_VERSION.
No input, token, key, path or native exception is echoed. Control JSON is at most
65536 UTF-8 bytes, with strict decoded duplicate-key, unknown-key, finite-number,
scalar-Unicode and version validation. API query parameters are not supported
by this slice; unknown query/method/body/path shapes fail closed.

GET /api/v1/capabilities requires the session and read checks. credentialConfigured
is only an environment-presence boolean, not a validated provider credential.
storageState is unavailable; connectionState unknown. LP-1/LS-1 are unqualified
pending integrated review; EF-1/PF-1 unavailable. limits is empty because this
slice does not claim any qualified document/model pipeline. All unfinished
command/document/job/event/asset/snapshot/recovery/bundle routes require session
checks then return503 SERVER_UNAVAILABLE. The in-process writer/receipt core now
exists (tooling/STORE.txt), but SSE, recovery/command HTTP, provider dispatch and
asset authorization remain unavailable.

The only accepted landing query key is progress-report; its value is ignored.
The shell includes its
trusted Developer UI return link from .progress-report/project.json. Presence,
ignored values, allowed navigation fragments and unflagged absence are tested.
That flag never bypasses session security or specifies an arbitrary URL.

SECURITY/VERIFICATION LIMITS

test:session uses real HTTP on loopback, a controlled clock with the actual
session store, actual POSIX mode/symlink checks, compiled CLI startup, and a
SIGKILL/restart child-process test. A test-only socket guard rejects every
non-literal-loopback connection. Production has no outbound/provider transport.
The session restart test retains a sentinel file; durable database/process tests
now live in test:store. It does not prove durable jobs. Root launch.json is
metadata; writer.lock has separate OS-held ownership and a durable writer epoch.

The bootstrap ordering check executes the actual prelude in a VM and observes
served HTML/CSP. P1a.3 adds actual Chromium browser cookie/fetch/fragment/history and hostile
site tests. The full browser/OS Q26 matrix remains unqualified. SEC05
user filename/prompt/archive rendering and SEC04 retained/withheld asset,
thumbnail/range safety remain P1b/P2 work; blanket unavailability is not safety
qualification. POSIX modes are checked, but another OS account was not used.
Same-OS-user or compromised-OS processes are outside the pairing defense.
No performance, native/AT, Windows, HTTPS or deployed/proxy qualification is
claimed. There is no paid call, publishing or live sibling modification.

ANONYMOUS REPORT NAVIGATION
A same-site, user-activated top-level GET / navigation without Origin may load
only the anonymous shell (Sec-Fetch-Mode:navigate, Dest:document, User:?1).
This lets the independent loopback report link open the editor. Exact Host and
query checks remain; cross-site, fetch, iframe, asset and all API requests retain
the original strict checks. The display flag grants no authentication.
