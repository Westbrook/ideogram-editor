# D11 runtime byte audits

`browser-d11.mjs` observes actual delivered bytes and actual executed JavaScript
in the production page and dedicated workers. It joins those observations to
`browser-d11-build.mjs`'s freshly verified build inventory. Resource Timing and
Chromium network byte counts remain distinct from independently computed gzip
sizes. Whole emitted artifacts count once in each scope; duplicate emitted files
and lockfile version multiplicity remain visible.

The collector uses V8 precise coverage. This prevents optimized execution, and
early worker attachment pauses new workers until observation is installed. The
constructor performs no coverage enablement; `begin({byteAudit:true,...})` is an
explicit additional audit. Its receipts always contain
`timingSamplesReusable:false`. These visits must never become scored S or R34
timing samples. The finite additional cohorts, primes, cache separation, owned
processes, and original whole-job time budget belong to the campaign runner.

Create the collector before the first navigation, call `begin` before the
declared navigation or actual public feature action, then `snapshot` at the
ready boundary and `close` before returning the process to ordinary work:

```js
const collector = await createBrowserD11Collector({
  context, page, repo, output, origin, fixture, engine: 'chromium',
  cachePolicy: { httpCacheDisabledByRouting: false },
});
await collector.begin({ id: 'W1:cold:1', cache: 'cold', scope: 'startup', byteAudit: true });
// Perform the actual production navigation and ready assertions.
const d11 = await collector.snapshot();
await collector.close();
```

The caller must establish the cache-policy fact. Playwright request routing
disables HTTP caching, so a routed warm visit remains incomplete. Production
`no-store` responses may legitimately refetch; the collector reports their real
transfer, without converting a warm label into a cache-hit claim.

Startup measurements are `D11StartupJsGzipBytes`,
`D11StartupEvaluatedJsBytes`, and `D11StartupUiCssAndFontsGzipBytes`. They include
the fixed server bootstrap script. Authoring fonts and the text WASM appearing
at startup are reported as eager loading failures. The separately declared
`text-engine` scope requires real worker execution, the exact pinned WASM,
and actual authoring-font initialization. A retained raster canvas alone cannot
satisfy it; the dedicated byte audit must exercise the actual public native-text
layout workflow. Its measurements are `D11TextEngineRawBytes` and
`D11TextEngineGzipBytes`.

The optional `lazy-feature` scope requires an exact bundler feature ID and a
completed observed startup baseline. It counts newly evaluated artifacts while
retaining shared startup code separately. Dynamic imports already executed at
startup are not deferred features. This capability does not manufacture missing
feature audit cells in the plan.

Every snapshot writes an exclusive hashed artifact containing resource byte
metadata, execution identities, font status identities, and the build inventory.
Request payloads, pairing fragments, DOM text, raw font names, and browser-read
script source are not retained. Browser source and response bytes are read
transiently to verify their hashes. Bounded producer metadata and fixed server
bootstrap derivation inputs are retained for independent offline verification
of the byte inventory. Unknown scripts, changed byte identities, unsupported engines, failed
or late worker attachment, worker termination before collection, resource loss,
and changing execution inventories remain explicit missing evidence.

The D11 registry provides absolute byte targets and ceilings. Runtime audit
rows carry `source:'separate-byte-audit'`; ordinary timing aggregation must defer
those rows to the separate audit receipts. The C build audit remains a separate
scope, and a runtime receipt never substitutes for its required build cohort.

Build receipts require complete static role classification, including explicit
exclusion of text-engine files from ordinary lazy-feature closures and evidence
that authoring assets do not enter the startup closure. Runtime startup and
text-engine observations can still report their actual bytes when static call
boundaries are ambiguous; they expose that build limitation in
`roleClassification`. A runtime lazy-feature claim also requires the matching
complete static deferred-feature classification.

The production startup role context is the union of W0's empty-shell readiness
and W1's document readiness through the actual public Open action at the H
profile of 1440×900 CSS pixels and DPR 2. Its boundary label
`document-ready-via-Open` names that union's document path; it does not assert
that W0 opens a document. Panel code loaded by Open therefore belongs in this
startup allowance. W2 retains its separate scored R05 navigation cohort without
acquiring a required W0/W1 D11 byte-audit cohort.

Runtime receipts record the viewport and device scale observed in the page,
along with the actual completed empty-shell or Open boundary. When static role
classification is complete, observed startup JavaScript must fit its verified
allowlist. The source proof uses the exact retained public registration
implementation and source invocation chain; a package name or dynamic-chunk
label alone grants no exemption from startup accounting.
