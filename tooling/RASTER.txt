P1b.4 CANONICAL RASTER INTEGRATION — CP-1 v1

This slice is a local, durable raster service plus an isolated conversion-review
consumer. It starts at approved e8b9f1a379becd97365242cc0a3b1c9d703bcfcb.
It does not attach layers to an editor document, edit history, adopt provider
results, deliver an external saved file, or complete a native/platform/PERF
qualification. P1b.5 owns document/history integration; P1b.7 owns editor controls;
P1c owns mask authoring; P2 owns request containment and provider adoption.

PUBLIC BOUNDARY

Use the existing authenticated protocolVersion1 command envelope, with strict
schemaVersion1 body fields, original command/session/correlation/transaction IDs,
null documentId/revision and EMPTY_EXPECTED_VERSIONS for these workspace assets:

  PrepareRaster {assetId}
  ReviewRaster {assetId}
  ApproveRaster {assetId,reviewId,reviewHash}
  ComposeRaster {width,height,layers}
  ExportRaster {assetId}

Each layer is {assetId,transform:[a,b,c,d,e,f],opacity,mask}; mask is null or
{assetId,mapping:"document-luminance-alpha-v1",inverted:boolean}. Layer order is
explicit bottom to top. Inputs and masks must be approved canonical-raster assets.
Layer masks have exact document dimensions; this v1 boundary admits only recorded
identity document mapping. A later authoring command must explicitly prepare a
mapped mask rather than quietly reinterpret it. Rasterized text contributions can
use this same boundary later; no text shaping/rasterization is implemented here.

POST /api/v1/commands uses existing 202 durable-pending /200 receipt semantics.
GET /api/v1/commands/:id exposes pending operationId/phase or the terminal receipt.
The sole writer journals original bytes, canonical hash and operationId before202.
Retry the original envelope byte-for-byte; sessionId remains provenance while the
fresh authenticated cookie is the current transport authority. Foundation, asset
and raster command IDs share one uniqueness boundary, including racing requests.
Startup resumes only local preparation already journaled; there is no external job.
Resource failure keeps the exact pending identity in waiting-for-resources, with
original input retained and private diagnostics. Retry after releasing resources
or reopening the backend; no quality, radius or product-dimension reduction occurs.
Invalid encoded input receives a terminal rejected receipt and diagnostic reason.

PrepareRaster consumes an owned pending-decoder original and emits a distinct
AssetRegistered raster-preview with an actual safe image/png. The original stays
retained, unknown and withheld; its signature never grants usable raster authority.
ReviewRaster emits RasterReviewPrepared. Read the exact review at
GET /api/v1/assets/raster-reviews/:reviewId. It binds owner, current cookie hash,
writer epoch, decoded manifest/pixel identity and expiry (at most30 minutes).
ApproveRaster requires that exact review and returns a canonical-raster logical
asset sharing the exact preview bytes. Approval does not decode or bake again.
Session renewal/restart expires the old review; obtain a fresh review.
Approval now journals its own pending command before202 and cooperatively proves
the preview PNG, raw pixels, manifest, extracted ICC/EXIF and original-source
closure in the shared IO queue. It checks private file identities again at commit.
Missing/corrupt/substituted dependencies produce a terminal MISSING_ASSET receipt
with RASTER_DEPENDENCY_MISSING/CORRUPT details. Repair never changes that receipt;
submit a new command after repair with a still-current review (or obtain a new one).
Authority is bounded by review, absolute/idle session expiry and the live cookie
binding. A restart cannot restore a pending approval's session authority: the
original command is retained and rejected RASTER_REVIEW_EXPIRED. A committed
approval still replays its exact receipt across restart. These rules add no
editor/history command, external delivery or automatic repair.

GET /api/v1/assets/:assetId/raster returns the typed immutable manifest.
GET /api/v1/assets/:assetId/content uses existing owned, safe-content verification,
proof/range/session fences, measured MIME and no-store/nosniff/sandbox headers.
No raw hash/path route was added. ExportRaster emits canonical-png from frozen
canonical-raster pixels. The export asset is durably available, not confirmation
that a user-selected external destination has been saved.

PIXEL AUTHORITY AND GEOMETRY

src/raster/core.ts is the sole CP-1 arithmetic path. Pipeline identity includes
cp1-f64-triangle-area-v1 and the SHA256 of the complete pinned codec receipt.
Native straight sRGB RGBA8 -> linear premultiplied transform -> document-aligned
R16 layer coverage -> opacity -> straight sRGB Q8 contribution K -> bottom-to-top
Normal fold in binary64 -> final straight sRGB Q8. Q8 is clamp(floor(255*x+.5)).
Computed zero alpha writes RGB0 on arithmetic paths. Original hidden RGB is retained.
Integer-grid identity/translation with no mask and opacity1 copies all four bytes;
empty stack is transparent zero; singleton returns K exactly. Capture a singleton
ComposeRaster for K, or the explicit full ordered stack for stage3. Persist that
asset identity; render/capture/export consumers must not invent another pre-path.
F01 white opacity.1 is K alpha26 and over black90. F04 108 vs subgroup109 remains a
prohibition on unsafe flattening under retained overlays, owned by later adoption.

Coordinates are pixel edges with samples at cell centers. Affines must have finite
coefficients and a finite nonzero determinant/inverse. Inverse row Euclidean norms
set source-axis minification spans max(1,hypot(row)). Reconstruction is separable
triangle/bilinear. For span>1 integrate that triangle analytically over the source
axis box; span<=1 evaluates it at the center. This sealed convention is not a
polygon-area affine filter under shear. Precision is binary64, fixed summation
order, source zero extension and no exterior/tile-edge coefficient renormalization.
Support is1 for span<=1 and span/2+1 otherwise. footprint() records a conservative
finite source envelope including support; file reads use global source coordinates.
Compute cores128 square and immutable views512 square share coefficients/halos.
Very large footprints stream source rows rather than lower sampling quality.

R16 import coverage is Q16((.2126*linearR+.7152*linearG+.0722*linearB)*alpha*65535).
Mask inversion is65535-M. Core feather has a globally normalized finite triangle,
product in2D and one final R16 quantization, zero extension by its Coverage source,
radius0/<=1 identity, radius<=64. It is a pure core function, not a durable mask edit
or a provider-domain containment implementation. Core preserve() copies S exactly
at M0, selects mapped candidate at M65535, and blends linear premultiplied values
otherwise. Full CP05–CP16 domain, expansion/clipping, request and adoption workflows
remain unimplemented. No claim that the full16-case campaign is complete.

STORAGE AND IDENTITY

Raw pixels are a private immutable row-major RGBA8 object. The manifest describes
nonoverlapping512-square views and hashes of exact view bytes; these are tile views
of that object, not a directory of independently encoded PNG tiles. A pixel identity
hashes ordered tile hashes, extent and complete pipeline identity. A separate
manifest hash captures sources, transforms, masks, opacity, kernel/precision/edge,
footprints, original/profile/orientation references and input manifests. No mutable
cache can substitute a newer source. Same pixels may share pixelIdentity while
changed dependencies produce a different manifest. Composition is streamed by
128-square cores; export copies the frozen raw object in1MiB chunks and encodes it
without a second bake. Historical pixel pipeline/identity stays unchanged on export;
its new PNG encoder identity is recorded separately in the manifest plan. PNG encoding uses filter0,8-bit RGBA,sRGB chunk and pinned
Node zlib level6 with64KiB IDAT chunks. Browser/GPU decode is display only.

RESOURCE ACCOUNTING AND LIMITS

One raster worker and two shared object/upload/asset IO slots; at most64 combined
asset+raster preparations. Worker old/young heap limits48/8MiB; runtime/native memory
is included in the plan and whole-process RSS checks, not equated with JS heap.
Pre-worker parser/native-load reservation128MiB. Bounded container parsing obtains
encoded dimensions and metadata cost BEFORE any native metadata/decode call; then
admission uses measured current
backend RSS plus the entire job allocation plan against512MiB. The Sharp decode plan reserves
2*RGBA bytes+32MiB native/color working for PNG/JPEG,5*RGBA+32MiB for WebP, one RGBA output,2MiB rows/tiles,4*metadata+4MiB
metadata/copies,4MiB PNG/hash IO,80MiB worker/runtime and16MiB concurrent backend IO/
control headroom. The optional conservative Sharp WebP path additionally reserves
4*encoded-file-bytes+1MiB: metadata and pixel loaders can each fall back from mmap
to a power-of-two GByteArray, and a released metadata allocation need not promptly
return RSS. The bounded path does not use that loader. Composition/export reserve8MiB rows/tiles (including two<=1MiB
row caches, K/output, Float64 accumulator, mask scalars and1MiB tile hashing),4MiB
metadata,4MiB PNG/hash IO,80MiB runtime and16MiB concurrent backend headroom. This
conservative plan is correlated with actual RSS; native internal allocators are not
individually instrumented. Parent snapshots/receipts retain their existing bounds.

Static WebP uses separately produced, sealed libwebp1.6.0 decoders: the retained
1.6.0-ideogram.1 Darwin arm64 artifact and the new1.6.0-ideogram.2-linux arm64/x64
artifacts. Existing codec binaries/profiles remain unchanged. Platform selectors
bind each producer to its exact installed CODECS profile; unsupported hosts fail
qualification before native execution. Node26.10.0's optional FFI loads only the
exact verified native artifact.
Its cumulative128MiB budget includes every decoder allocation, allocation headers,
page rounding, simultaneous old/new reallocations and64bytes per-block accounting
allowance. Allocation uses anonymous page-rounded mmap after reserving the full
charge; munmap releases the exact mapping before subtracting it. There is no
malloc-zone rounding or freed native arena retention. A source audit checks that
all upstream allocations enter these wrappers; threading is disabled and all
upstream codec symbols are hidden. The native API reports peak, remaining and
allocation-denied counts; success requires remaining=0 and peak<=admitted budget.
The app separately charges the exact RGBA output,256KiB native stack/IO,
metadata/copies, rows/tiles, PNG/hash,80MiB runtime and16MiB concurrent-backend
allowances. Its metadata reader copies only flagged ICCP/EXIF chunks after
admission, with the existing combined4MiB ancillary payload ceiling. ALPH is
encoded pixel data, charged through the native decoder instead of metadata.
The RIFF walk allows at most1024 chunks, checks cancellation and yields every64;
zero-length unknown chunks cannot grow unbounded bookkeeping. No Sharp metadata
accumulator, full-file mapping or encoded-input copy occurs on the bounded path.
The small EXIF reader reproduces the frozen IFD0 orientation interpretation;
other EXIF graphs are retained as original bytes and never expanded. Static
demux flags/order and ignored-alpha behavior retain the frozen decoder semantics.
Where its demuxer ignores ALPH, an exact VP8/VP8L chunk is streamed to a private,
disk-reserved temporary RIFF and removed after decoding. This changes framing
only, never encoded image samples. Original source identity/timestamps are fenced
across metadata, optional frame copy, native decode and normalization.

The entire decoder lifetime occurs in one native call. The separately sealed
output bridge owns one anonymous RGBA mapping, passes it to the unchanged decoder,
and writes an owned raw file through bounded IO. Every return path releases
decoder allocations and the output mapping before JavaScript resumes, including
invalid streams, capacity failure and short reads. Worker termination waits for native cleanup; document/request ownership
checks still run afterward. Input descriptor size/identity/timestamps and actual
output dimensions are checked before pixels can be returned. Budget exhaustion
is an explicit resource failure; original bytes and durable operation identity
remain available through the existing preparation/recovery path. No partial pixels,
resize, alternate filter, codec or quality fallback is published.

Lossy, lossless and alpha use the same bounded decoder. P3 conversion then calls
the SAME existing sealed LittleCMS2.19.1 library with the exact qualified P3/sRGB
profiles, RGB8/perceptual/NOCACHE settings and96KiB strips, preserving alpha and
hidden RGB. Darwin uses its public LCMS symbols. The Linux build hides those

The native wrappers own cleanup in one call. Fixed
profile conversion happens after all decoder allocations have been released;
the native working reservation covers the larger of128MiB decode and32MiB fixed
color-conversion phases, not simultaneous full-image copies. ICC/EXIF originals
and explicit normalization review are retained. Unsupported optional FFI/loader
availability selects the original Sharp path and its conservative admission
before pixel work; it never changes decoder after a smaller plan is admitted.

New canonical rasters use an aggregate codec identity that binds the unchanged

JPEG EXPORT MEMORY RECIPE

New JPEG exports record encoderTransport=jpeg-file-baseline-v1. Their already
resampled, explicitly matted RGBA bytes are streamed through the canonical PNG
encoder into a private intermediate. Sharp reads that file and writes directly
to an exclusively opened read/write descriptor through /dev/fd. Source/sink
descriptors stay open through native completion; output identity is rechecked and
flushed, and the private intermediate is removed on success or failure.

The pinned settings are reviewed quality rounded to 1..100, 4:4:4 sampling,
baseline sequential coding, quantization table0, with trellis quantization,
overshoot deringing, scan optimization and Huffman-table optimization disabled.
Disabling Huffman optimization changes lossless entropy representation and file
size, not the quantized coefficients. Tests compare actual quantization tables,
decoded pixels, ICC and sampling with the earlier optimized recipe. The transport
marker prevents reinterpretation of its different encoded bytes.

The earlier marker-free JPEG recipe remains available only for retained portable
recomputation. Its raw input stream accumulated and concatenated full buffers;
optimized encoding also allocates two complete coefficient arrays in the sealed
mozjpeg binary. Its corrected reservation accounts for those arrays and the
growing encoded buffer, with explicit resource refusal when needed.

New file encoding initially reserves two RGBA surfaces plus32MiB above the
existing nondecode plan. This is a conservative estimate, not an enforced native
allocator cap; full-process RSS measurement remains required. Its disk plan adds
the temporary PNG and a stuffed-entropy upper bound of512 bytes per8x8 component
block for all three components plus2MiB of tables/ICC/markers. It never assumes
encoded JPEG is smaller than the raw source. No quality or dimension downgrade
is used to fit memory. tests/raster/jpeg-memory.test.mjs covers pixel/quantization
parity, exclusive output, cancellation and failure cleanup; those functional
checks do not constitute25MP or complete lifecycle resource qualification.

EXPLICIT WEBP OUTPUT LIFETIME (2026-09-30 CONTINUATION)

The initial bounded decoder eliminated excessive codec allocations but still
returned a full RGBA Node Buffer. Its first whole-writer25MP white tests passed
(318046208B lossy,301203456B lossless), while a same-writer repetition refused
the second import: resident baseline293257216B plus reservation345628928B
exceeded536870912B. Preserve artifacts/a-r01-diagnostic/*-product-01/02 receipts;
this failure is not erased by the single-import passes. A supplementary compiled
source audit records the unchanged server09 closure after that failed run.

The new webp-file-v1 transport uses a separately produced/sealed webp-output
bridge. It maps one page-rounded anonymous RGBA region within a synchronous C
call, invokes the existing sealed decoder, writes the owned0600 raw file through
bounded64KiB pwrite operations, and unmaps before returning. Color conversion
similarly reads that file into one temporary anonymous map, calls the unchanged
sealed P3 converter, writes it back, and unmaps. No pointer crosses a JavaScript
continuation. Anonymous mappings avoid sparse file-backed mmap SIGBUS on disk
exhaustion; read/write failures remain explicit errors. Output mappings are
reported separately from the decoder's cumulative native allocation cap.

The existing full raw-output reservation is retained, with page rounding covered
by the native stack/IO allowance. EXIF transforms use two128-square file tiles,
alpha normalization uses64KiB, and tile hashing reuses a single<=1MiB scratch
buffer. These changes bound allocation lifetime; they do not lower reservations,
force collection, resize pixels, change quality, or omit original assets.

New manifests bind both decoderBuild and outputBuild to an exact aggregate
profile. All earlier marker-free, opaque-incremental and buffered bounded
profiles remain registered with their original hashes for portable replay.
Producer reproduction, functional parity/failure gates, repeated whole-writer
measurements, adversarial inputs and actual platform campaigns remain separate
checks. The new source design alone does not close A-R01 or qualify the full
25MP envelope; receipts must identify the final compiled/native profile measured.

An injected OS munmap failure is explicitly a failed release: native outputRemaining
stays nonzero, the loaded bridge instance retains its lease, and the application
records that retained allocation with the original resource-refused operation.
That lease is local to the loaded library instance; unloading/reloading it does
not establish a process-wide poison flag. Such an OS cleanup fault is outside
the ordinary zero-retained-allocation guarantee. Existing measured whole-process
RSS is still included before every new admission; no failed release is counted
as free memory. Untouched virtual mappings are not claimed to be bounded by an
RSS check. The native injected-fault receipt and bounded failure diagnostics must
retain this limitation rather than describe successful cleanup.

A Linux producer test exposed coarse filesystem timestamp behavior: an immediate
same-size write can leave the observed stat stamp unchanged. The failed attempt
is retained. The Linux-specific follow-up fixture explicitly advances mtime and
therefore tests rejection of an observed stamp change, not detection of every
possible same-size byte mutation. Descriptor/extent/stamp fences do not claim an
atomic filesystem snapshot. The existing private immutable object ownership
contract is unchanged; this transport does not introduce a hostile same-UID
filesystem security guarantee.
