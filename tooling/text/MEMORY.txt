P1c.1 reservation model (all counts in bytes)

Authority: src/text/memory.ts textMemory is shared by every controller and bundled
font loader in one app realm. R35 text <=128MiB, within shared R18 CPU <=512MiB.
Other consumers can book category other. The later writer must bridge this realm
ledger with process/backend accounting before acceptance; this task has no product
UI or backend integration and does not claim a process-wide RSS admission proof.

Native heap: initial16MiB / hard maximum32MiB in the compiled WASM descriptor.
Book the full32MiB, including all native font bytes, FreeType/HarfBuzz/ICU scratch,
shape/line/glyph caches and direct RGBA surface. No second count of in-heap data.
A failed native allocator does not increase the heap; its guard returns/refuses
before writing through a null pointer. A trapped native job terminates
its worker, without accepting a candidate or touching previous accepted pixels.

Engine startup: 32MiB + 6*WASM_bytes +4MiB fixed glue/adapter allowance. The six
WASM-sized stores cover incoming stream/copy chunks, Blob, ArrayBuffer, WebCrypto
snapshot and compile inputs. After worker-ready completes the loader scope,
resident booking is32MiB +2*WASM_bytes +4MiB (compiled module and retained input
allowance). These are ownership transitions, not promises of synchronous GC.
The healthy resident heap stays booked. Explicit successful terminate ends app
ownership of private worker allocations, independently of measured RSS or GC.

Font loader: reserve5*fileBytes before fetch/hash; then retain1*fileBytes for the
cached immutable input Blob. Concurrent loads share the pool and coalesce per ID.
No hidden font fetch occurs at startup. Cache is only the four sealed bundled
assets. User-supplied original files remain caller-owned and are counted during
preparation; the caller must account for originals retained outside this service.

Request preflight scans Unicode scalars and bounded metadata before arrays,
clones, worker creation or native allocation. Its full peak must fit before any
worker creation. Main metadata is a bounded whitelist; font Blob handles alias
inputs. The sole clone boundary is postMessage to the worker. Font reservation
is4*uniqueFontBytes (caller Blob + worker backing + parser buffer + digest snapshot),
minus only caller Blob bytes already booked by the owned loader. Native copies
are inside the booked heap. Buffers verified by the parser are reused for native
registration, rather than allocating another ArrayBuffer per font.

Current streamed-layout profile:
G=max(64,8*scalarCount) remains an expansion ceiling. The native export quotas
are runs<=min(G,max(64,ceil(scalars/8))+logicalLines-1) and
lines<=max(logicalLines,min(G,max(64,ceil(scalars/4)))); rectangles<=2G.
Each LF boundary reserves one additional possible native run, since even short
paragraphs can create separate runs. The existing expansion allowance remains;
blank paragraphs and a trailing LF are preserved without charging fake glyphs.
Actual unusually fragmented geometry can refuse at these independent workspace
quotas. No text/font/glyph truncation or reduced fixture is used to fit a quota.
The native count pass checks glyph/run/line quotas before JS shaped arrays exist;
native rectangle vector size is checked before export.

Native exported arrays cost14G+12runs bytes; the current run's copied glyph
bounds cost at most16G. W=30G+1024runs+512lines+256KiB books those stores,
per-run ArrayBuffer/typed-array/typeface wrappers, line/metric records, bounded
writer fragments and fixed adapter objects. In-heap native arrays still belong
to the separately booked32MiB heap. Index/scalar/duplicate-cluster/missing-range
bookkeeping I=128*(UTF16length+UTF8bytes+scalarCount+3). Raster
R=ceil(width)*ceil(height)*4, with4R for JS readback, Blob and hashing/clone phases.

The adapter serializes each native line/run/cluster into UTF-8 chunks <=64KiB.
It retains no complete layout object graph or complete JSON.stringify string.
The current frame object is emitted explicitly as width then height, independent
of request object insertion order. Other field order and number spelling remain
byte-identical. The retained7a4dbc6c streamed profile keeps its preceding frame
order: verification reads only its bounded known header to reproduce one of the
two recorded orders, requires identical dimensions, and still compares exact
complete layout hashes. It retains streamed quotas; it never enters the older
480-scalar canonical comparison path. L is an enforced serialized-output capacity, not a claim that every
allowed glyph/run/line already produced1024 bytes. Its ceiling is the minimum
of8MiB, the preceding small-input estimate, and the remaining128MiB lane after
resident engine +4F+4R+I+W+64KiB request+2MiB verifier scratch+64KiB loan metadata,
divided by3. F counts every current supplied font backing, including a backing
already booked by a loader. Before each append the writer checks L. It clears
chunk ownership after Blob creation and before hashing; the overlapping phases
are at most chunks+Blob or Blob+ArrayBuffer+digest snapshot, bounded by3L.
Request peak=fontReservation+4R+3L+I+W+64KiB. The backend uses3F while the caller
retains F. Its current-profile comparison streams the staged file hash using a
64KiB buffer and compares exact generated layout hash, without duplicate JSON
graphs or canonical strings. It books2MiB scratch and checks both startup and
resident peaks including caller F+64KiB loan metadata against the same128MiB.
Unrelated live caches still consume the actual shared pool and may refuse.

Retained streamed renderer profiles through6f7be5be keep their exact prior
runs<=min(G,max(64,ceil(scalars/8))) quota, W and resulting output/verification
capacity. Internal profile routing selects this reservation before preparation
and verification; it does not reinterpret accepted bytes under the new quota.
The current profile alone adds the LF allowance. No layout, native heap or total
text/CPU cap changes, and all layout/pixel hash comparisons remain exact.

Retained older canonical renderer profiles keep the original G/runs/line quotas and old
6L request+2L comparison scratch model. Their serialized capacity estimate must
already fit8MiB; actual retained layout bytes can increase comparison booking.
This deliberately preserves their previous small-layout semantic comparison
without extending that allocation path to newly admitted maximum-size input.

Each worker caches up to16 exact faces already loaded, inside its32MiB heap.
Cache uses no native eviction refund to admit new faces. An accepted run must
match this request's supplied fonts even if other exact faces are cached.
Per-job paragraph, builder, font metric wrappers, raster surface/allocation and
native returned rectangle buffers are explicitly released. Known CJK repeated
registration/eviction failures are preserved; retained face reuse is the chosen
bounded ownership policy. Historical occupancy can report FONT_CACHE_CAPACITY or a guarded native copy
allocation failure. The client terminates/releases that private worker and tries
once in a fresh worker with the same complete supplied set, token and original
deadline. It never retries indefinitely or substitutes/truncates fonts. If the
fresh job itself cannot fit, it refuses and preserves the draft/old appearance.
A valid changed current set is not a new lifetime-font limit.

Bounded rectangle extraction distinguishes a zero-length Float32Array (valid
empty geometry) from null (quota exceeded). Nonempty results are native-owned
views; the adapter copies retained geometry and frees their native allocation.


Prepared output: before acceptance, verify token, geometry/Blob sizes and font
identity. Retain a reservation for text/layout/RGBA plus non-loader-owned font
inputs. releasePrepared(value) means the caller has durably consumed or dropped
all candidate references; it is an ownership release, not a GC assertion. The
caller must not use it to excuse continued unbooked retention. Retained saved
appearance and caller drafts are never modified by refusal/cancellation.

One active job and one latest pending request are permitted. A microtask queue
coalesces obsolete requests before starting new worker work; tokens fence late
results. Healthy idle worker heap/provider remains booked. On cancel, deadline,
fatal failure or dispose, detach listeners/timers, call stock Worker.terminate,
and drop private worker/job references. Successful termination releases those
private reservations exactly once. It does not execute native finally blocks or
certify physical memory reclamation. Shared caller Blobs, saved/prepared output
leases and external resources keep their distinct owners. Only an actual API
failure retains uncertain booking; no guessed timer or synthetic counter refund.
Primary platform contract: https://html.spec.whatwg.org/multipage/workers.html#terminate-a-worker

Repeated cancellation/new preparation and disposal are usable in the same realm.
The browser test harness still separately observes actual worker-close events
before one controlled public OPFS reset. Runtime reservation release is never a
substitute for that storage gate. Unknown/unclosed storage state fails without reset.

This is a conservative owned-allocation model. Engine/JS implementation overhead
and GC/RSS correlations, full WXn/WXs envelopes, repeated lifecycle campaigns and
physical-platform performance remain P3. Passing these bounded checks does not
qualify those campaigns or make backend reservations automatic.
